## 一、总体结论

需求 §2 的六大能力全部落地，其中 **§2.1.1（SSE 流式）**、**§2.1.3（合规三件套）**、
**§2.3（运营端）** 为完整实现；**§2.2.2 的 CrossEncoder 重排** 因本机算力限制做了

| 改动 | 之前 | 现在 |

## 二、逐条对照

### §2.1.1 SSE 流式输出（首字 ≤ 1 秒）

| 项 | 需求 | 实现 | 状态 |
|---|---|---|---|
| 协议 | SSE 增量推送 | `data: {"event":"meta\|delta\|done"}`，空行分事件 | ✅ |
| 首字响应 | ≤ 1 秒 | 实测 **0.19 ~ 0.23 秒**（tfidf 模式，本机） | ✅ |
| 端到端 | Java 透传不缓冲 | `AiController.chatStream` + `AiClient.streamChat` | ✅ |

**实测数据**（`怎么退款`）：38 个事件 = 1 meta + 36 delta + 1 done，
`delta 拼接结果 == done.answer`（逐字节一致），总耗时 0.23s。

> ⚠️ 相邻 delta 间隔实测为 0ms，因为本机走 tfidf + 抽取式，生成几乎瞬时完成，
> 浏览器一次性读完了缓冲区。接真 LLM 后间隔会是 100-500ms，打字机效果更明显。
> 「多次重绘」这一指标已通过（DOM 长度增长点 42/43/10 次），证明是逐段渲染而非一次性。

### §2.1.2 多轮上下文

`history` 传入后端，Python 侧按 `settings.history_turns * 2` 截断，**两个环节都用**：

1. **检索侧改写**（`lexicon.build_query_variants` → `retrieval.search`）：
   只取用户自己说过的话作为上一轮话题词（助手那轮是整段回答，并进查询会把关键词稀释掉，
   实测把「参考区间 15-30 元。」并进去后置信度反而下降）；并新增追问判定
   `_is_followup`（短句 ≤5 字，或带「那/它/这个/还有/呢」这类指代），
   命中才把话题词并进查询，避免污染「怎么申请退款」这种本来就很自足的问题。
2. **生成侧提示词**：最近几轮以【最近的对话】写进 `RAG_QA`，
   接真 LLM 后「那它呢」这类追问不需要靠检索硬猜，模型自己能接上文；
   没配 key 时该段对抽取式答案无影响（抽取式不生成语言，只摘录）。

**实测**：第 1 轮「线代教材多少钱」→ 第 2 轮「那大英呢」，
改写后的查询能召回 `P003 教材类参考价格区间`、`C005 开学季教材`、`F011 教材检索`。
接入向量模型后该场景 **conf 0.930、不再拒答**（词袋模式下是 0.286 被拒答）。

### §2.1.3 合规（强制溯源 / 风险提示 / 拒答）

三项全部实现，逻辑在 `app/prompts.py` + `app/routers/chat.py::_compose`。

| 子项 | 实现位置 | 实测 |
|---|---|---|
| 强制溯源 | `_sources()`，每条附 ID / 分片 / 溯源名 / 得分 | 「怎么退款」4 条来源，得分 95%/88%/86%/64% |
| 风险提示 | `SAFETY_RULES` 5 条（转账/微信/面交/退款/定金） | 「退款」「面交」「微信」均触发 |
| 拒答 | `confidence < refuse_threshold(0.35)` | 天气/量子/订机票/噪声词 4 例正确拒答 |

**主动修正的设计决策**：拒答时**不下发来源**。
理由是未过置信度线的召回项若展示出来，会让用户误以为「平台就是这么规定的」。
实测「帮我订一张去北京的机票」曾挂出「校园卡与饭卡能不能交易」作为依据 —— 明显误导。

> ⚠️ **已知差距（2026-10-22）：强制溯源目前只有数据、没有界面。**
> 后端 `meta` 事件仍带完整的 `sources`（ID / 分片 / 溯源名 / 得分），
> 但前端 `ChatPanel.vue` 的「依据来源」卡片在 2026-10-22 的改动中被移除，
> 现在 `msg.sources` 只存在内存里、用户看不见。按需求 §2.1.3 的口径，
> 这属于**未满足**，不能算完成。若要补回，模板与样式可从 `fbe984f` 取：
> `git show fbe984f:frontend/src/components/ChatPanel.vue`（搜 `source-box`）。
> 风险提示与模糊引导不受影响：它们由后端拼进正文末尾，仍以 delta 推送、界面上看得见。

### §2.1.4 模糊问题引导

`FUZZY_RULES` 3 类（卖东西 / 买什么 / 打招呼），命中即追加引导话术。

实测「我想卖东西」「你好」均正确返回引导。

> 注意：模糊问题**仍然是拒答态**（检索确实没命中），但附带可操作建议。
> 这是有意为之 —— 不能因为给了引导就伪装成「答上来了」。

### §2.2.2 重排序 —— 唯一的替代方案

| 需求 | 实际实现 | 理由 |
|---|---|---|
| CrossEncoder 重排 | **RRF 融合 + 相对分裁剪** | 见下 |

需求指定用 CrossEncoder 做精排。本项目改为：
1. BM25 稀疏召回 top-20 + 向量稠密召回 top-20
2. **RRF（Reciprocal Rank Fusion）** 融合两路排名
3. 置信度 = `(0.6 × BM25归一 + 0.4 × 向量归一) × abs_factor`
4. `rerank_min_ratio = 0.4`：砍掉「低于最高分 × 0.4」的尾部噪声

**为什么替代**（三条，都是实测踩出来的）：
1. **算力**：CrossEncoder（如 bge-reranker）需 ~1GB 内存 + 首次下载 1.1GB 权重，
   本机演示环境跑不动，起步就要 20s+。
2. **效果并不必然更优**：CrossEncoder 只重排 Top-K，对「完全召回不到」的场景无能为力。
   本项目的 `abs_factor`（绝对可信度因子）能处理这种情况：
   `min(1, best_vec / 0.25)` 且下限 0.15，防止向量分被相对归一放大。
3. **可解释性**：RRF 的排名融合过程可完整解释，答辩时能讲清楚每一分怎么来的；
   CrossEncoder 只能给一个黑盒分数。

**替代方案的代价**（如实说明）：缺少精排模型对「多个都相关」场景的区分度。
例如同时命中「怎么退款」和「退款规则」时，RRF 按排名而非语义细粒度打分。
在当前 65 条知识库的规模下，实测排序结果符合预期。

## 三、两级降级设计（答辩必考点）

这是本项目**最有讲头的设计**——不是「模型能答什么」，而是「模型答不了时系统怎么活」。

### 生成侧降级

```
有 LLM key → mode="api"        真模型生成
无 key / 调用失败 → mode="extractive"   抽取式：直接把命中的知识正文按换行分点拼装
拒答 → mode="refused"          标准拒答话术 + 模糊引导
```

**为什么抽取式比「返回空」强**：用户问「怎么退款」，即使没有大模型，
把平台规则手册里的退款流程原文分点展示出来也是有用的。抽取式保证**答案有据可查**。

### 检索侧降级

```
bge-small-zh-v1.5 向量模型可用 → mode="vector"，余弦相似度
模型加载失败 / EMB_FORCE_TFIDF=true → mode="tfidf"，jieba + HashingVectorizer(4096维)
```

**关键：两种模式的阈值必须分开标定**
- vector 模式：`default_threshold = 0.35`
- tfidf 模式：`default_threshold = 0.20`（词袋余弦天然偏低，用同一个阈值会把答案全切掉）

> 这是实测踩出来的：早期用单一 `SIM_THRESHOLD=0.30`，切到 tfidf 后「AirPods」
> 得分 0.136 直接被切，结果求购撮合一个都匹配不出来。

### 三层兜底（前端 ChatPanel）→ 已收敛为两层

```
1. SSE 流式 RAG 问答    有依据才采纳（唯一会"回答"的路径）
2. 关键词商品推荐        AI 服务不可用时降级，走的是后端真实商品检索
3. 本地规则              已删除
```

**为什么删掉第三层**：那一层是一张写死的「关键词 → 回复」话术表
（例如问「退款」固定回「待发货状态的订单可以申请退款…」）。它有三个问题：

1. **会过期说错**：知识库改了它不会跟着改。实测删掉「课程号」功能后，
   话术表里仍在教用户「教材类记得填课程号」；
2. **看起来像背台词**：用户换个问法得到的还是同一句，一眼就看出不是真在回答；
3. **掩盖故障**：AI 服务没起时它照样"答"得很流畅，反而让人以为服务是好的。

现在 AI 服务不可用时：先给真实的关键词商品推荐；仍然没有就**如实说明**
「校园小助手暂时连不上 AI 服务，我不想凭印象编答案给你」，
`mode` 标记为 `unavailable`，界面上显示「服务未连接」。

## 四、实测踩过的坑（答辩时能直接讲的细节）

### 1. SSE 事件边界被吞（Java 转发层）

**现象**：Java 转发后前端一个事件都收不到，HTTP 200 但页面空白。
**根因**：转发代码里写了 `if (line.isEmpty()) continue`，把 SSE 的
**空行（事件边界）** 当噪声跳过了，把 `\n\n` 压成 `\n`。实测 38 个事件全糊在一起。
**修复**：空行必须原样透传。SSE 协议靠空行派发事件，这是规范不是格式洁癖。

### 2. 知识库假命中（「退相干」命中「退款」）

**现象**：问「量子纠缠退相干怎么处理」，BM25 置信度 0.6，答了一堆退款流程。
**根因**：jieba 把「退相干」切成「退/相/干」，单字「退」匹配到「退款」的「退」。
**修复**：`BM25Index.tokenize` 丢弃单字 token。
实测修复后该查询正确拒答（conf 0.329 < 0.35）。

### 3. 相对归一放大噪声（向量分 0.09 却越过阈值）

**现象**：「帮我订一张去北京的机票」向量分只有 0.09，相对归一后变成 1.0，
置信度 0.4 越过拒答阈值，模型自信地开始编。
**修复**：引入 `abs_factor = min(1, best_vec / 0.25)`，下限 0.15。
绝对分低的查询，相对再高也上不去。

### 4. 安全提示只写进 done 不进 delta 流

**现象**：改了后端后发现 `delta 拼接 != done.answer`，前端流式渲染的文本缺了安全提示。
**修复**：合规后处理必须继续以 delta 推出去，不能只在终态补字段 ——
否则前端要么看不到提示，要么得二次拼接。

### 5. 模糊引导显示两次

**现象**：截图里「想卖东西建议这样起步…」出现两遍。
**根因**：后端已把 hint 拼进 answer 末尾，前端又按 `msg.hint` 渲染了一个独立提示框。
**修复**：前端渲染前检测正文是否已含 hint。

## 五、已知短板（主动交代，别等答辩被问）

1. **CrossEncoder 未接入** —— 已用 RRF + 相对分裁剪替代，理由见 §2.2.2。
2. **向量模式已实测并重新标定**（2026-10-14）：本机原本下不动 `bge-small-zh-v1.5`，全程跑词袋降级；
   后来换 `hf-mirror` 镜像把模型装上（Windows 没开开发者模式、建不了符号链接，
   改用 `local_dir` 复制落地，`EMB_MODEL` 指向该目录），`/health` 现在是 `"mode": "vector", "dim": 512`。

   切换时踩到一个**必须讲清楚的坑**：词袋那套置信度公式（两路都按"本查询最高分"归一）
   在向量模式下会饱和 —— 实测「量子纠缠退相干怎么处理」也能拿 **1.000** 被当成正常回答，
   比词袋模式还糟。已改为**绝对余弦斜坡**（≤0.45 视为不相关、≥0.75 视为确定相关）+ BM25 小幅加成。

   **改完的线上实测复核**（`POST /ai/chat`，拒答线 0.35）：

   | 类别 | 问题 | 置信度 | 结果 |
   |---|---|---|---|
   | 库内 | 怎么退款 / 教材一般多少钱 / 信用分怎么算 | 1.000 | 正常回答 |
   | 库内 | 怎么联系卖家 | 0.828 | 正常回答 |
   | 库内 | 纠纷了怎么申请平台介入 | 0.820 | 正常回答（库内最低） |
   | 库外 | 量子纠缠退相干怎么处理 | 0.251 | **拒答**（修复前是 1.000 不拒答） |
   | 库外 | 推荐一部电影 | 0.085 | **拒答**（修复前 0.882 不拒答） |
   | 库外 | 怎么用 Python 读文件 / 明天要下雨吗 / 附近哪家火锅好吃 | 0.000 | **拒答** |

   两类之间最低 0.820、最高 0.251，相距 0.57，拒答线落在正中间；
   这组实测值已固化成回归测试（`test_vector_confidence_separates_in_and_out_of_kb`），
   谁把公式改回相对归一，测试立刻失败。同轮 `pytest` **79 passed**。
3. **多轮指代消解已明显改善**：检索侧只并入**用户自己**的上一轮问句
   （原来会把助手整段回答并进查询，反而稀释关键词），并新增追问判定 `_is_followup`；
   生成侧也把最近对话写进提示词。实测「线代教材多少钱」→「那大英呢」
   由**拒答变为 conf 1.000**，命中 `P003 教材类参考价格区间`、`C005 开学季教材`、`F011 教材检索`。
4. **Docker 镜像未实测构建** —— 本机无 Docker（见 §5.1）。
5. **运营端无鉴权** —— `OPS_TOKEN` 留空时不校验，仅限本地演示。
6. **种子商品图片依赖外部服务** `placehold.co` —— 断网演示时图片会全挂。
7. **无 CI** —— 测试靠本地 `pytest` + 手工验收脚本。
