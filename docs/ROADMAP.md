## 担保交易状态机（B2 已落地）

与普通二手交易的区别：**货款先托管在平台，买家确认收货后才放款给卖家**。
订单状态与资金状态两条线一一对应，所有流转都必须经过 `OrderStateMachine` 校验。

```
待付款 ──付款(买家)──> 待发货 ──发货(卖家)──> 已发货 ──确认收货(买家)──> 已完成
  │ 资金:未付款         │ 资金:平台托管          │ 资金:平台托管        │ 资金:已放款
  └──取消(买家)──> 已取消                    └──申请退款(买家)──> 退款中
                  资金:未付款                                    │ 资金:平台托管
                                                                 └──同意退款(卖家)──> 已退款
                                                                                    资金:已退回
```

| 校验项 | 行为 |
|---|---|
| 非法流转（如「待付款」直接变「已发货」） | 400，并提示当前状态允许流转到哪些状态 |
| 越权操作（买家点「标记发货」） | 400，「该操作只能由卖家发起」 |
| 终态再操作（已完成 / 已退款 / 已取消） | 400，「是终态，不能再流转」 |
| 退款或取消 | 商品自动重新上架 |

**前端不重复维护状态规则**：订单 JSON 里带 `nextActions`（`[{status, label, actor}]`），
界面按当前用户身份过滤后直接渲染按钮 —— 非法操作在界面上根本不会出现。

## 纠纷仲裁（B4 已落地）

入口只有一条：**买家对「已发货」的订单申请平台介入**。判定由 `role = admin` 的账号作出，
只有两种结局 —— 支持买家退款，或驳回诉求、视为交易完成并把货款放给卖家。

```
已发货 ──申请平台介入(买家)──> 仲裁中 ──裁定(管理员)──> 已退款（货款退回、商品重新上架）
  资金:平台托管                资金:平台托管   └────────> 已完成（视为完成，货款放给卖家）
```

- 卖家「拒绝退款」：`退款中 → 已发货`（退回原状），买家不服可再申请平台介入
- 仲裁期间资金**继续冻结在平台**，谁也不能动
- 裁定结果直接驱动订单状态机流转，不是另起一套状态
- 管理端 `/admin` 只在 `role = admin` 时出现在导航栏

演示账号：`admin / admin123`（管理员）、`test / test123`（卖家）、
`buyer01 / buyer123`（买家小明）。
