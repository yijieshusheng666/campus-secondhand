## 担保交易状态机（B2 已落地）

与普通二手交易的区别：**货款先托管在平台，买家确认收货后才放款给卖家**。
订单状态与资金状态两条线一一对应，所有流转都必须经过 `OrderStateMachine` 校验。

```
待付款 ──付款(买家)──> 待发货 ──发货(卖家)──> 已发货 ──确认收货(买家)──> 已完成
  │ 资金:未付款         │ 资金:平台托管          │ 资金:平台托管        │ 资金:已放款
  └──取消(买家)──> 已取消                    └──申请退款(买家)──> 退款中
                  资金:未付款                                    │ 资金:平台托管
                                                                 └──同意退款(卖家)──> 已退款
                                                                                    资金:已退回
```

| 校验项 | 行为 |
|---|---|
| 非法流转（如「待付款」直接变「已发货」） | 400，并提示当前状态允许流转到哪些状态 |
| 越权操作（买家点「标记发货」） | 400，「该操作只能由卖家发起」 |
| 终态再操作（已完成 / 已退款 / 已取消） | 400，「是终态，不能再流转」 |
| 退款或取消 | 商品自动重新上架 |

**前端不重复维护状态规则**：订单 JSON 里带 `nextActions`（`[{status, label, actor}]`），
界面按当前用户身份过滤后直接渲染按钮 —— 非法操作在界面上根本不会出现。

## 纠纷仲裁（B4 已落地）

入口只有一条：**买家对「已发货」的订单申请平台介入**。判定由 `role = admin` 的账号作出，
只有两种结局 —— 支持买家退款，或驳回诉求、视为交易完成并把货款放给卖家。

```
已发货 ──申请平台介入(买家)──> 仲裁中 ──裁定(管理员)──> 已退款（货款退回、商品重新上架）
  资金:平台托管                资金:平台托管   └────────> 已完成（视为完成，货款放给卖家）
```

- 卖家「拒绝退款」：`退款中 → 已发货`（退回原状），买家不服可再申请平台介入
- 仲裁期间资金**继续冻结在平台**，谁也不能动
- 裁定结果直接驱动订单状态机流转，不是另起一套状态
- 管理端 `/admin` 只在 `role = admin` 时出现在导航栏

演示账号：`admin / admin123`（管理员）、`test / test123`（卖家）、
`buyer01 / buyer123`（买家小明）。

## 求购反向撮合（C1 已落地）

与商品方向相反：**先有需求，再由系统反向去找在售的商品**。两个方向用了不同策略：

| 方向 | 场景 | 策略 | 理由 |
|---|---|---|---|
| 需求 → 商品 | 求购页「找找看匹配的宝贝」 | **语义检索** | 买家写的是自然语言（「想找一副能降噪的耳机」），只有语义召回才能命中「索尼 WH-1000XM5 头戴式耳机」；AI 不可用时退回关键词匹配 |
| 商品 → 需求 | 发布商品成功后 | **规则匹配**（分类 + 预算 + 关键词） | 要对每条求购各算一次相似度，调用次数多；规则更快且不依赖 AI 服务 |

**求购不设绝对相似度阈值**，改用「相对最高分」+ 字面证据的三档门槛：

| 入选条件 | 含义 |
|---|---|
| 语义分 ≥ 最高分 × 0.6 | 相似度足够接近最佳匹配 |
| 语义分 ≥ 最高分 × 0.35 **且**关键词命中 ≥ 1 处 | 语义 + 字面双证据 |
| 无语义结果时，关键词命中 ≥ 3 处 | AI 服务没启动时的纯关键词兜底 |

**为什么不是单一看相对分**：实测「想找一副能降噪的耳机」最高分只有 0.24，
0.35 倍仅 0.084 —— Apple Watch（0.10）、小米 14（0.09）这类无关商品全都过了阈值。
加"字面证据"这档后，它们被排除，结果只剩索尼耳机。

**检索词只用「标题 + 补充说明」，不拼分类**：分类名出现在同类目每件商品的文案里，
拼进去会让整个类目互相"相似"（与 A4 定价踩过的是同一个坑）。

**结果可核对**：响应里带 `scanned`（参与比对的商品总数）、`semanticCount`（语义候选数）
和每条命中的 `reason`（相似度 + 通过了哪些校验），界面上直接展示。独立交叉验证脚本
（用 jieba 词级打分另一套算法）确认：API 返回的正是独立评分最高且满足分类/预算/在售的商品。

分类、预算、在售状态三道过滤都在 Java 侧做，与语义检索的职责划分保持一致。

## P4 三个 AI 功能的落地方式

| 功能 | 做法 | 关键取舍 |
|---|---|---|
| **A4 智能定价** | 语义召回 + Java 侧关键词补扫 → 取价格中位数与四分位区间 | **不把分类拼进检索词**（分类名让整个类目互相相似，实测会把建议价从 ¥2399 抬到 ¥6499）；**同时补扫全部商品**，因为 AI 索引只有在售商品，而定价需要已售/历史价格作参考；样本 < 2 件时如实标注「粗估」 |
| **A6 内容风控** | 规则层（违禁品 / 诈骗话术 / 手机号正则）永远可用，配了 LLM 再叠加模型判断 | 三级判定：`block` 直接拒绝发布、`warn` 提示确认、`ok` 放行。**刻意"宁可漏报不误杀"**：留联系方式只 warn，避免正常交易被卡死。前端提示 + **后端发布接口独立校验**，绕过前端也拦得住 |
| **A3 图片识别** | 可配置的多模态接入层（OpenAI 兼容协议，智谱 glm-4v 之类同样适用） | 本机没有视觉模型，所以做成**接口与界面就位、配 key 即用**；未配置时如实返回 `available:false`，前端提示手动填写，不假装识别成功 |

### A3 怎么启用

在 `ai-service/.env`（或环境变量）里补三项，重启 AI 服务即可，**不需要改代码**：

```
VISION_BASE_URL=https://open.bigmodel.cn/api/paas/v4
VISION_API_KEY=你的key
VISION_MODEL=glm-4v-flash
```
